## Failures / workarounds

1. Fork `git config` identity missing -> set repo-local
   richardoros <risoo5@hotmail.com>; amended the PLAN.md commit (force-push
   with lease; branch was 2 min old, single author).
2. First seam run: `BENCH_FAIL: empty completion or zero eval tokens` - buun
   fork timings keys differ from upstream; server log showed real values
   (736 pp / 26.9 tg). Fixed key names, reran (746 pp / 26.7 tg), then fixed
   ttft semantics (prompt_ms, not per-token x1000): final 705.7 / 25.7.
3. Driver crashed: `output_dir` str vs Path in `create_workspace` - fixed by
   passing `Path` (Hyperloom bug-compat: callers pass Path, signature untyped).
4. `MODEL` env is required by the script; first driver-style run without it
   failed fast (by design, set -u).
5. H0.0+ rename test inversion: `if python3 ... port-in-use; then fail`
   had the bash semantics inverted. measure.py returns rc=0 when port is
   free, rc=1 when in use; the script must use `if ! python3 ...` to
   fail-closed on the occupied case. Fixed: `if ! python3 ...; then fail`.
   Added `test_cli_exit_code_invert_for_bash` to prevent regression.
6. `bench_envs` argument is not forwarded to the subprocess env by
   `_run_scriptable_benchmark`; the env vars that reach the script have
   to be in `bench["envs"]`. Documented in the smoke driver.
7. test_profile_and_kernel_handlers.py:91 asserted
   `_GFX_TO_RUNNER.get("gfx1100") is None` - H0.0 broke this when it added
   `gfx1100` to the map. The H0.0+ rename moves the gfx arch out of the
   gpu_type key, so the test's original intent is true again on the fork;
   the assertion is updated to assert the new fork-specific mapping.
