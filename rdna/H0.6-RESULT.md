## H0.6 closure commits (5 items, all landed)

| # | Item | Resolution |
|---|---|---|
| C1 | Signal re-raise recursion | `RestoreTrap._restore_and_reraise` now restores the previous signal handler **before** `os.kill(self, sig)`. The previous handler calls SIG_DFL after restore, so the re-raise terminates the process cleanly. **Verified in a real child process** via `test_signal_reraise_does_not_recurse_in_child`: a counting handler ran exactly once. |
| C2 | `h05_baseline` requires explicit fixture | The callable raises `RuntimeError` if `HYPERLOOM_FIXTURE_PATH` is missing or the file lacks `prompt_tokens`. The `bench` CLI's `bench` subcommand accepts the 4th positional arg = fixture path, loads it, fail-closes on GGUF SHA mismatch. `cli.py:--fixture-path` propagates via env. |
| C2.5 | Chunked GGUF hashing | `bench/measure.py` now streams 1 MiB at a time when SHA-ing the model — no more `open(...).read()` on a 20 GB GGUF. |
| C3 | Swap-I/O activity gate | `_swap_used_bytes` is kept for telemetry only. New `_swap_io_rate(sample_seconds=1.0)` reads `/proc/vmstat:pswpin,pswpout` and computes pages/s. The gate blocks on rate, not on cumulative occupancy. |
| C4 | Celery measured CPU | `_celery_cpu_percent()` sums `top` %CPU across all `celery.*worker` processes (idle workers = 0% → tolerated). The previous "Celery present → BLOCK" rule is gone. `build/Celery` reasons in the audit now mention "build" and "Celery" separately. |
| C5 | PID vs PGID drain primitives | `_wait_for_pids_to_clear(pids)` uses `os.kill(pid, 0)`. New `_wait_for_pgids_to_clear(pgids)` uses `os.killpg(pgid, 0)`. Both share `_alive_after_deadline(probe=...)`. |
