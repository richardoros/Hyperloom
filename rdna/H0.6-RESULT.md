## Pipeline (H0.6.1)

```
snapshot pre_state
    ↓
acquire exclusive flock (~/.cache/hyperloom/evaluator.lock)
    ↓
resolve MainPIDs of --allow-service services (pre-drain)
    ↓
stop allowlisted services (systemctl stop, never pkill)
    ↓
wait briefly for VRAM / PIDs to clear (drain_wait_seconds)
    ↓
attribute foreign PIDs (BDF-resolved; UNKNOWN if not attributable)
    ↓
BLOCK if any UNKNOWN or foreign owner remains
    ↓
run H0.5 measurement in a daemon thread (deadline = --timeout-seconds)
    ↓
on exit (SUCCESS / FAILURE / TIMEOUT / SIGTERM / SIGINT / exception):
    - kill candidate PID (MeasurementContext.register_candidate)
    - restart stopped services
    - release lock
    ↓
fresh post-state probes (service_state + listener_state +
                          production_health_ok + gpu_telemetry +
                          attribute_to_lab_gpu, NEVER copied)
    ↓
emit lifecycle audit artifact
```

## What is NOT in H0.6

* **Real N=5 baseline.** The lab GPU is still occupied by foreign
  llama-server processes (notably the qwen38-vktq on port 18179,
  using Vulkan turboquant on 24+ GiB of VRAM). Per amendment 4 the
  orchestrator does not kill them. Until they are stopped or
  allowlisted, H0.6 cannot reach the PASS branch on a real
  measurement. The dry-run path is fully exercised and the audit
  artifact proves fresh post-state.
* **Per-process PID-to-GPU-UUID map for Vulkan-only processes.** BDF
  matching is in place; UUID-level per-process attribution requires the
  per-device `/sys/class/drm/cardN/device/uevent` walk (already
  supported via `_drm_card_to_bdf` but UUID normalization pending).
* **TIMEOUT thread cleanup.** The measurement thread is daemonized,
  so a TIMEOUT leaves a Python thread alive in the background after
  `run_lifecycle` returns. Cleanup is left for H0.7 once it matters.
* **Auto-drain of qwen38-turboquant.service.** Intentionally NOT in
  `DEFAULT_ALLOWLIST()`. The operator must add it explicitly with a
  one-line comment.
